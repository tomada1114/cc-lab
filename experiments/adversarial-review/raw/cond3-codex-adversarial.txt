# Codex Adversarial Review

Target: branch diff against main
Verdict: needs-attention

出荷不可。テナント境界を越える情報漏えい、Bearerトークンの記録、共有済みタスクを削除できない整合性欠陥、ページ欠落があります。

Findings:
- [critical] 任意ユーザーが他人のタスクと共有先を取得できる (src/tasks.ts:253-268)
  GET /tasks/:id/shares は認証されているだけで、要求者が所有者か確認せずID指定されたタスク本体と共有先を返します。連番IDを列挙すれば、タイトル、説明、期限、共有相手のユーザーIDをテナント境界を越えて取得できます。
  Recommendation: c.get('user') と getTaskForUser() で所有権を検証し、所有者以外には404を返してください。別ユーザーによる拒否を検証するテストも追加してください。
- [high] 例外発生時にBearerトークンがログへ漏えいする (src/app.ts:26-32)
  onError が Authorization ヘッダー全体を平文で出力します。未処理例外を踏んだユーザーの再利用可能な資格情報が、ログ基盤やログ閲覧者へ漏えいし、アカウントの乗っ取りにつながります。
  Recommendation: Authorizationをログから完全に除外してください。追跡には相関IDと、取得可能な場合のみ認証済みuser.idを使用してください。
- [high] タグ付け・共有後のタスク削除が外部キー制約で失敗する (src/db.ts:54-64)
  task_tags と task_shares の外部キーに ON DELETE CASCADE がありません。node:sqliteでは外部キー制約が有効なため、関連行があるタスクのDELETEは500になります。特に共有解除APIも存在しないため、一度共有したタスクはAPI経由では削除不能です。
  Recommendation: 関連外部キーへON DELETE CASCADEを設定するマイグレーションを用意するか、トランザクション内で関連行を削除してからタスクを削除してください。タグ付き・共有済みタスクの削除テストも追加してください。
- [medium] 1ページ目が先頭のlimit件を恒常的に飛ばす (src/tasks.ts:43-60)
  pageは1始まりで既定値も1ですが、offsetをpage * limitで計算しています。そのためGET /tasks?limit=2は先頭2件を返さず、3件目から始まります。現在のテストは件数の上限しか検証せず、この欠落を検出できません。
  Recommendation: offsetを(page - 1) * limitに修正し、pageとlimitを正の整数として検証してください。各ページの具体的なID順序を検証するテストを追加してください。
